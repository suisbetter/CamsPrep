## Operational gotchas learned this session (read before repeating work)

1. **LiteSpeed cache purging**: the generic "Purge All" / "Empty Entire
   Cache" buttons in the Toolbox did **not** reliably propagate to the
   QUIC.cloud CDN edge layer in testing — verified via `x-qc-cache` header
   staying `hit` with an unchanged `max-age` after clicking them. **"Purge
   By... → URL" (enter specific URLs, one per line) is the only method
   confirmed to force a fresh edge miss (`x-qc-cache: miss`) reliably.**
   Always verify via a fresh `fetch(url, {cache:'no-store', credentials:'omit'})`
   after purging — never trust the admin UI's own "purged" toast alone.
2. **WPCode "Update"/"Save Snippet" button clicks can silently fail** —
   caught this twice. A `left_click` on the button via a stale `find`-tool
   `ref` sometimes does nothing. **Always verify a save actually persisted
   by hard-reloading the snippet edit page (`navigate` with `force: true` if
   there's an unsaved-changes dialog) and re-reading the CodeMirror value —
   don't trust the in-page state right after clicking.** A more reliable
   click method: `document.querySelectorAll('button')` + match by exact
   text, then `.click()` via `javascript_exec`, rather than a cached `find`
   ref.
3. **Text field `ctrl+a` select-all sometimes leaves a stray leading "a"
   character** when immediately followed by typing (a timing/event-order
   issue, seen twice on Rank Math's meta-description textarea). Safer
   pattern: click into the field, `Home`, `Delete` (or `ctrl+a` then
   `Delete` then a short `wait` before typing), and always screenshot-check
   the result before saving.
4. **Rank Math's Schema Builder "Advanced Editor" (raw JSON view) caused a
   genuine page hang** — multiple tool calls timed out in a row (30s+ each)
   until a forced navigate reset the tab. Avoid it. For schema fields not
   exposed in the normal Schema Builder UI (like `priceSpecification`),
   prefer a WPCode output-buffer snippet that string-replaces the rendered
   JSON-LD (same pattern as snippet 10500), rather than fighting the
   Advanced Editor.
5. **Screenshot tool has intermittent ~30s timeouts** that are *not* a real
   page freeze most of the time — confirmed by successfully navigating or
   running `javascript_exec` immediately after a "timed out" screenshot.
   When a screenshot times out, try `get_page_text` or a `javascript_exec`
   check before assuming the page is actually broken.
6. **Theme File Editor is disabled** (`Appearance → Theme File Editor`
   returns "Sorry, you are not allowed to access this page") — no direct
   theme-file access from WP Admin. No FTP/SFTP/hosting-panel credentials
   are available to this session either. Anything that genuinely requires
   editing a theme template file (not just filtering its output) is blocked
   until the user provides that access.
7. **Two docs vanished from disk twice this session** —
   `seo-fix-plan-2026-07-30.md` and `unimplemented-audit-fixes.md` — never
   intentionally deleted, most likely a side effect of an earlier `/seo
   audit` background subagent touching the working directory (one subagent's
   own report noted its writes to the project dir were blocked by
   permissions, implying others may have partially succeeded). Both were
   restored via `git checkout HEAD -- <file>` and committed immediately.
   **If either file is missing again, that's the likely cause — restore
   from git history, don't assume the content is gone.**
